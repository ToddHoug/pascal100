# IEEE Std 696-1983, the S-100 bus standard

Source: [IEEE_696_1983.pdf](#) (ANSI/IEEE Std 696-1983, *IEEE Standard 696 Interface Devices*,
sponsor: the Standards Committee of the IEEE Computer Society; approved by the IEEE Standards Board
June 10, 1982 and by ANSI September 8, 1983; 38 pages with a text layer. The tables and figures
were read from the page images, because the text layer scrambles them.)

Page numbers below are the printed page numbers. The printed page is the PDF page plus 2.

This is a distilled emulation reference for pascal100's **IEEE-696 bus type** (DESIGN.md §4.0,
pascal100 note). It keeps what a guest or a board can observe: the address, data and status
lines, the 8/16-bit transfer protocol, the interrupt and reset lines, and the pin list. The
electrical, timing and mechanical specifications (sections 3 and 4) and the bus arbitration
protocol (2.8.3) are named only, because pascal100 does not model them.

## 1. Masters and slaves (2.1, p. 12)

- A **bus master** starts every bus cycle and drives the address, status and control lines
  ("type M signals"). There is one **permanent master** (usually the CPU) and up to **16
  temporary masters**. A temporary master takes the bus for some cycles and gives it back: a
  **TMA** (Temporary Master Access) cycle. The standard renamed DMA to TMA, because a temporary
  master can run I/O cycles too (Foreword).
- A **bus slave** watches every cycle and answers when it is addressed. A slave needs only the
  subset of signals it uses.

## 2. Address bus (2.2.2, pp. 12-13)

- 16 or 24 lines. "All bus masters shall assert A0 through A15, but may assert lines A16 through
  A23 if extended address capability is desired."
- **Standard memory addressing:** A15-A0, 64K. **Extended memory addressing:** A23-A0, 16M.
- **Standard I/O addressing:** A7-A0, 256 devices. **Extended I/O addressing:** A15-A0, 64K devices.
- NOTE (2.2.2.4): "The I/O device address has traditionally been duplicated onto the high order
  address byte, A15-A8. While this is considered acceptable procedure, it is not recommended for new
  designs as it complicates expansion to extended I/O device addressing. Standard I/O slaves shall
  not rely solely on the high order address byte for address decoding."

**Table 4, address usage (p. 12):**

| Cycle | Standard addressing | Extended addressing |
|---|---|---|
| Memory read, memory write, M1 (op-code fetch) | A15-A0 | A23-A0 |
| Input, output | A7-A0 (see 2.2.2.4) | A15-A0 |
| Interrupt acknowledge, halt acknowledge | none | none |

**PHANTOM\*** (2.2.2.3, 2.2.9.6): when it is active, phantom memory slaves are enabled and normal
memory slaves are disabled, for both read and write cycles. "All normal memory slaves shall have
the capability of being disabled in response to PHANTOM\*." Open collector.

## 3. Status bus (2.2.3, p. 13)

Eight lines, driven by the current master. The mnemonics start with a lowercase s:

| | Line | Meaning |
|---|---|---|
| 1 | sMEMR | memory read |
| 2 | sM1 | op-code fetch |
| 3 | sINP | input |
| 4 | sOUT | output |
| 5 | sWO\* | write cycle (active low) |
| 6 | sINTA | interrupt acknowledge |
| 7 | sHLTA | halt acknowledge |
| 8 | **sXTRQ\*** | sixteen-bit data transfer request (active low) |

There is **no sSTACK**: pin 98, the Altair's sSTACK, is ERROR\* in 696 (section 9).
Status memory write is not a line: `sMemoryWrite = (NOT sOUT) AND sWO` (2.2.3.1).

L = low, X = don't care:

|---|---|---|---|---|---|---|---|---|---|
| Memory read | B | H | L | H | L | L | L | L | H |
| | W | H | L | H | L | L | L | L | L |
| Op-code fetch | B | H | H | H | L | L | L | L | H |
| | W | H | H | H | L | L | L | L | L |
| Memory write | B | L | L | L | L | L | L | L | H |
| | W | L | L | L | L | L | L | L | L |
| Output | B | L | L | L | H | L | L | L | H |
| | W | L | L | L | H | L | L | L | L |
| Input | B | L | L | H | L | H | L | L | H |
| | W | L | L | H | L | H | L | L | L |
| Interrupt acknowledge | B | L | X | H | L | L | H | L | H |

| Halt acknowledge | | X | X | H | L | L | L | H | X |
| Idle | | L | L | H | L | L | L | L | X |

A 16-bit request is possible on every data cycle, I/O and interrupt acknowledge included.

## 4. Data bus and the 8/16-bit protocol (2.2.4, 2.6, pp. 14, 23-25)

- 16 lines. For a **byte** transfer they are two unidirectional 8-bit buses: data out DO7-DO0 and
  data in DI7-DI0 (2.2.4.1). For a **word** transfer they are one bidirectional 16-bit bus
  (2.2.4.2).
- Two lines control the ganging: **sXTRQ\*** (status, from the master: "I request 16 bits") and
  **SIXTN\*** (from the slave: "a 16-bit transfer is possible", open collector, 2.2.6.4). When
  both are active the buses are ganged: the **even**-addressed byte on DO7-DO0, named ED7-ED0, and
  the **odd**-addressed byte on DI7-DI0, named OD7-OD0.
- **Byte order:** the standard gives no significance to the bytes (Foreword). The rule is only
  that a byte at an address with A0 = 1 is on OD7-OD0, and a byte with A0 = 0 is on ED7-ED0, so a
  byte reads the same in 8-bit and 16-bit modes.
- **Addresses:** for a word, A1 through A15 (A23 when extended) select the word, and "A0 is
  specified as being 0 for word transfers". A0 does not enter into the decoding of a word
  reference (2.6.4.2).
- **Memory organization** (2.6.4, Fig. 4, p. 24): a 16-bit memory is an even-byte bank and an
  odd-byte bank. For a byte reference (sXTRQ\* not active) A0 = 0 selects the even byte and
  A0 = 1 the odd byte. For a word reference both banks are active.
- **An 8-bit slave in a 16-bit system** (2.6.1, 2.6.5): SIXTN\* "allows the use of 8-bit memory
  boards in a 16-bit system without modification". If the addressed slave cannot do a 16-bit
  transfer, it does not assert SIXTN\*. **The master** then responds in one of two ways:
  - **byte-serial response** (2.6.5.1, recommended): "circuitry should be included on bus masters
    to conduct the requested 16-bit transfer as two consecutive byte operations, thus assembling
    the requested 16-bit word while holding the master in a wait state"; or
  - **error response** (2.6.5.2): "an error condition shall result immediately, with ERROR\*
    asserted".
- ⚠ **The standard does not say which byte the byte-serial response transfers first.** It says
  only "two sequential single-byte transfers" (2.6.1) and "two consecutive byte operations"
  (2.6.5.1). The order is the master's design.
- SIXTN\* must meet the timing of the ready lines (2.6.5.1, Fig. 6; 3.10).

## 5. Control lines (2.2.5, 2.2.6, pp. 14, 18)

- **Control output** (from the master, mnemonics start with p): pSYNC (start of a cycle),
  pSTVAL\* (stable address and status), pDBIN (read strobe), pWR\* (write strobe), pHLDA (hold
  acknowledge).
- **Control input** (to the master): RDY and XRDY (ready; both must be true. XRDY is "commonly
  used by front panel devices to stop and single step bus masters"), INT\*, NMI\*, HOLD\*, SIXTN\*.
- **MWRT** (2.2.9.5): `MWRT = pWR* AND (NOT sOUT)`. It shall be generated at only one point in
  the system (traditionally the front panel).

## 6. Interrupts (2.2.6.2, 2.2.8, 2.9, pp. 14, 18, 32-33)

- **INT\***: maskable, a level, held until the master serves it. The master may answer with an
  interrupt acknowledge cycle that reads a vector from the data bus during pDBIN. "Since no
  address information is asserted during an interrupt acknowledge cycle", several interrupt
  controllers must be daisy chained or polled (2.9.1.2).
- **NMI\***: not maskable, a **negative-going edge**, needs no acknowledge cycle (2.2.6.2, 2.9.2).
  It may also serve ERROR\* and PWRFAIL\*.
- **VI0\*-VI7\***: eight vectored interrupt levels, VI0\* the highest, held as levels until
  served, open collector. They are inputs to an interrupt controller slave, which drives INT\* and
  answers the acknowledge cycle.

## 7. Bus transfer and arbitration (2.2.7, 2.8)

- **HOLD\*** (2.2.6.3): a temporary master requests the bus; the permanent master may mask it.
  **pHLDA** grants it.
- **TMA0\*-TMA3\*** (2.2.7.1): the priority of up to 16 temporary masters, arbitrated on the
  bus (2.8.3). **ADSB\*, DODSB\*, SDSB\*, CDSB\*** (2.2.7.2): disable the permanent master's
  address, data out, status and control drivers during a transfer.
- pascal100 models HOLD\*/pHLDA and the TMA priority (section 10). It does not model the
  driver disables.

## 8. System utilities (2.2.9, p. 19)

- **System clock ϕ** (2.2.9.2): from the permanent master; it times every bus cycle.
- **CLOCK** (2.2.9.3, pin 49): 2 MHz ±0.5%, not related to any other signal, for counters, timers
  and baud rates.
- **Resets** (2.2.9.4), three lines:
  1. **RESET\*** resets all bus **masters** (pin 75);
  2. **SLAVE CLR\*** resets all bus **slaves** (pin 54);
  3. **POC\***, power-on clear (pin 99), is active at power-on and after the rising edge of
     PWRFAIL\*, "and shall cause SLAVE CLR\* and RESET\* to be asserted". POC\* lasts at least 10
     ms; RESET\* and SLAVE CLR\* at least 5 µs. Pin 54 and 75 say each "must be active with POC\*
     and may also be generated by external means".
- **ERROR\*** (2.2.9.7, 2.10.2, pin 98): a generalized error line, for example "memory parity
  error, write to protected memory, inability to accommodate 8-bit slaves". It should be
  implemented as a trap; its falling edge will generally cause an NMI\*.
- **PWRFAIL\*** (2.10.1, pin 13): active at least 16 µs before the regulators drift; its rising
  edge causes POC\*.
- **NDEF** (2.2.9.8): three lines a manufacturer may define, as jumper options. **RFU**
  (2.2.9.10): four reserved lines.

## 10. What pascal100 models

| Feature (section) | pascal100's IEEE-696 bus type |
|---|---|
| Extended memory address A16-A23 (2.2.2.2) | Modeled. A board that decodes only A0-A15 answers in every 64K segment. |
| Extended I/O address A0-A15 (2.2.2.5) | Carried on every I/O cycle. Boards decode A0-A7 (2.2.2.4 note). |
| sXTRQ\*/SIXTN\*, the 16-bit transfer (2.6) | Modeled: one cycle when the slave answers SIXTN\*. Otherwise the master does the byte-serial response, in its own order. |
| Status bus with sXTRQ\*, no sSTACK (2.2.3) | sXTRQ\* is carried. The status byte is the 8080-style one inherited from altairsim; the 8085 core still sets its stack bit (to be settled with the CPU 85/88 board). |
| PHANTOM\*, INT\*, VI0\*-VI7\*, NMI\*, HOLD\*/pHLDA, RDY/XRDY | Modeled. |
| TMA0\*-3\* arbitration (2.8.3) | Modeled: each DMA board has a priority, 0-15. The highest gets the bus first and keeps it until it drops HOLD\*. A machine with two masters at one priority does not load or run. |
| RESET\*, SLAVE CLR\*, POC\* (2.2.9.4) | Two reset kinds: POC\* (power on), and a bus reset that is RESET\* with SLAVE CLR\* together. |
| CLOCK (2.2.9.3, pin 49) | Modeled: `BusClock` (`src/core/busclock.h`), 2 MHz, independent of the CPU clock. The SS-1's 8253 and math chip count it. |
| ERROR\* (2.10.2), PWRFAIL\*, MWRT, NDEF, RFU, driver disables, sections 3 and 4 | Not modeled. |
